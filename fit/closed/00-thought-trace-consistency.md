thought trace consistency. Currently, a streamed thought trace renders formatting correctly, while a trace that's been finalized is all inline and collapsed. I'd like both of them to render the same, modeling the way that a streamed trace looks now.

### Decisions

- Symptom confirmed: finalized thoughts lose line breaks (the final body has no `white-space: pre-wrap`); chrome also differs from the live box.
- Use one shared component: the finalized box renders the same markup/classes/CSS as the streamed box (`details.block.meta.thinking-indicator done` with `.think-live`).
- Finalized box becomes a top-level log block immediately before the assistant answer block. Live and snapshot/history paths both use it.
- Summary keeps the status distinction: streamed `agent is thinking…` with pulse while active; finalized `thinking`, no pulse.
- Open state: both default collapsed. Opening the streamed box keeps the finalized box open in the same page view; no persistence across reload/snapshot (reopened sessions show it collapsed).
- Scope: live→final at `message_end`, snapshot/reconnect/reopen and "load earlier" through the shared render path, plus a small `ARCHITECTURE.md` wording update.
- Export is out of scope: `/export` is generated by Pi's own `export_html`, not this client.
- Client-only change. No protocol, hub, or server changes.

### Edge cases

- Thought-only assistant message: thought box only, no empty labelled "pi" answer block.
- Whitespace-only or ANSI-only thought: no box.
- Multiple Pi thinking blocks: one box, blocks joined with a blank line.
- Long unbroken text wraps anywhere; no horizontal overflow at 390px.
- ANSI styling survives in both boxes.
- Text/tool calls stay in the assistant block after the thought box.
- No thinking: no box; assistant message unchanged.
- Reload/snapshot: finalized box collapsed again; no persistence.
- Tool-only assistant message: thought box first, then tool cards; no empty answer block.
- Empty message content: nothing rendered, no empty wrapper.

### Implementation notes

- Add a shared pure `thinkingBoxHtml`/`renderThinking` helper in `src/client/render.js`; `transcriptView.js` reuses it for live paints so markup and classes cannot drift.
- Wrap assistant snapshot entries in a neutral entry container so the thought box is a sibling before the assistant block while `data-entry`, windowing, full-entry replacement and reftag decoration keep working.
- Files expected: `src/client/render.js`, `src/client/transcriptView.js`, `src/client/transcript.js`, `src/client/transcript.css`, `test/render.test.js`, `ARCHITECTURE.md`.
